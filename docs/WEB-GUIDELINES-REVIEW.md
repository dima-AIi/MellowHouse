# Проверка интерфейса и доступности

Источник правил: [Vercel Web Interface Guidelines](https://raw.githubusercontent.com/vercel-labs/web-interface-guidelines/main/command.md), повторно прочитан перед финальной проверкой 19.10.2026. Проверены Razor, собственные CSS/JS и реальный Chromium DOM. Это целевая проверка, не заявление о полной сертификации WCAG.

Исправленные находки:

- `wwwroot/css/site.css`: HTML-атрибуты исходных размеров делали фотокатегории слишком высокими — добавлен управляемый `height:auto` с явными высотами только там, где они нужны композиции.
- `wwwroot/js/core.js`: toast с кнопкой отмены был вне native modal и становился недоступен — теперь он находится в активном диалоге; реальная отмена удаления проверена браузером.
- `wwwroot/js/cart-auth.js`: после обновления строки и сохранения настройки восстанавливается фокус соответствующей кнопки.
- `wwwroot/js/checkout.js`: исправление поля снимает его прежнюю ошибку и aria-invalid; смена получения очищает неприменимые ошибки.
- `wwwroot/css/site.css`: усилен цвет focus ring. Контраст действий #218354 на белом — 4.73:1, основного muted-текста #64706b на белом — 5.16:1.

Проверено:

- Кнопки и ссылки семантические; icon-only действия имеют названия, изображения — alt, поля — label.
- Есть skip link, visible focus, aria-live для уведомлений, Escape и native focus trap для диалогов.
- Главная с reduced motion полностью видима без принудительной анимации; прокрутка категорий прерывается пользовательским вводом.
- Фотокатегории — 4/2 колонки; популярные товары имеют кнопки и горизонтальное листание на телефоне.
- URL отражает вкладки и категории; есть прямые ссылки и восстановление положения.
- Проверены 390/768/1024/1440 px без горизонтального переполнения основных страниц.
- Удаление поддерживает отмену, очистка — подтверждение. Ошибки не уничтожают корзину.
- Все основные шрифты/фото локальные, размеры изображений заданы, ниже первого экрана используется lazy loading. У карточек подготовлен content-visibility для будущего большого каталога.

Оставшееся для последнего этапа: повторить проверку производительности и длинной прокрутки после наполнения ассортимента; проверить настоящий мобильный Safari/Android на устройствах и возможности установки PWA после публикации HTTPS.
