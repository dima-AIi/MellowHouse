# Полный перенос интерфейса Mellow House

30.10.2026. Версия витрины 26. Основа сравнения — b8eeab12e759645e526b44722d4eb74c061c2eb3 (первый этап).

## Результат

React + строгий TypeScript владеют всем интерактивным клиентским интерфейсом и панелью администратора. Общий типизированный ShopStore заменяет старые контроллеры. bridge и декларации legacy удалены. Backend остаётся на ASP.NET Core; схема, данные, права и API не меняются.

Перенесены вход по телефону/почте, регистрация, восстановление доступа, корзина, изменение вариантов и количества, гостевое оформление, сохранение черновика, оплата, личная ссылка заказа, статусы, отмена оплаченного заказа, профиль, история и повтор. Сохраняются чат, настройки блюд, FAQ, русское КБЖУ, избранное, поиск, установка PWA с главной и компактный мобильный интерфейс.

Админка перенесена полностью: каталог и архив, черновики и стоп-лист, фотографии PNG/WebP, категории и перенос товаров, конструктор опций и аллергенов, КБЖУ и предпросмотр, заказы и разрешённые переходы, ручной заказ, оплата при получении, частичные возвраты, клиенты и блокировки, восстановление доступа, отчёты, расходы, CSV, настройки и журнал действий.

Информационные тексты справочных страниц выводятся React из серверной разметки без скриптов и CSRF. Razor остаётся для маршрутизации и начального/read-only HTML. Это не перенос backend на JavaScript.

## Сохранение логики

- Сохранены URL, cookies, CSRF, ключ браузерной корзины v17 и формат чата v10. Приватные ссылки не попадают в публичный экспорт.
- Заказ, цена, часы кафе, город доставки, права, статусы и возвраты проверяются тем же сервером.
- Повторный сетевой запрос оформления/оплаты/отмены сохраняет ключ операции; изменение оформления создаёт новый ключ.
- Корзина работает до подключения. Подтверждение заказа требует API. Сверка локальной корзины идемпотентна; недоступные позиции видны и блокируют оформление.
- Быстрые изменения количества выполняются последовательно. Ответ старой ревизии не заменяет новую корзину; ответ другого владельца не применяется.
- Native fetch вызывается без привязки к объекту состояния; дата передаётся в формате yyyy-MM-ddTHH:mm, события input/change обрабатываются для полей даты.
- Вход команды использует поле login, клиентский вход — email. Неподтверждённая онлайн-оплата не означает начало приготовления.

## Дизайн

Сохранены зелёная палитра, фотографии, Golos и Oswald. Добавлены единые поля, диалоги, заметный фокус, плавное открытие корзины, спокойные реакции кнопок и карточек. Мобильная сетка, меню и подвал остаются компактными. При prefers-reduced-motion движения отключаются.

## Проверки

Production-сборка и строгий TypeScript; 42 теста новой реализации React/TypeScript; 140 серверных тестов; 33 совместимых проверки существующей логики и деплоя и 3 проверки полной React-сборки (всего 218). Тесты с моками дополнены реальным прохождением через локальный API, поскольку одни моки не обнаружили бы ошибку привязки native fetch или различие login/email.

Локальная браузерная проверка: добавление и настройка сырников, корзина, сохранение оформления, заказ гостя ко времени, демонстрационная оплата, принятие командой, совпадение статуса у клиента, отмена оплаченного заказа с тестовым возвратом; вход команды и отчёты; загрузка настоящего прозрачного PNG и сохранение тестового черновика. Продукционные данные при этих сценариях не изменяются.

Мобильный просмотр выполнен при 390 × 844: компактная сетка в две колонки, отсутствие горизонтального переполнения, открытие и закрытие мобильной навигации. Исправлена лишняя вертикальная прокрутка внутри полосы вкладок. Публикация дополнительно проверяется по версии и revision в storefront-build.json. Физическая установка PWA на iPhone/Android и настоящие банковские операции в эти проверки не входят. Оплата, коды и восстановление сохраняют существующий демонстрационный режим.

## Откат

Вернуть предыдущее развёртывание frontend/backend. Преобразование базы или обратная миграция данных не требуются. Кэш service worker повышен до v26.
