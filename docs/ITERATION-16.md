# Оформление заказа без регистрации

Гость может открыть оформление из корзины, указать имя и телефон, выбрать получение и оплату, затем посмотреть статус заказа. Вход больше не блокирует оформление. Кнопка «Войти — необязательно» сохраняет введённые поля и корзину.

После оформления гостю доступны:

- страница заказа в исходном браузере;
- копирование личной ссылки на один заказ, действующей 30 дней;
- добровольный вход и явное сохранение оформленного заказа в профиле;
- вопросы помощнику о собственных гостевых заказах этого браузера.

Общая история профиля, повтор заказа и персональные данные аккаунта требуют входа. Телефон и публичный номер заказа не используются как доказательство владения. Сохранение заказа в профиле не происходит автоматически по совпадению контактов.

## Доступ

GuestOrderAccess проверяет защищённую гостевую cookie либо ограниченный одним заказом токен ASP.NET Core Data Protection. Секрет передаётся во фрагменте ссылки и теле POST, а не в серверном URL. После проверки выдаётся HttpOnly-cookie с путём конкретного заказа. Все ответы API остаются private/no-store, CSRF продолжает проверяться.

После явного сохранения в аккаунте заказ меняет владельца и перестаёт быть гостевым: старые ссылки и гостевые cookie доступа больше не подходят. Истёкшая ссылка не мешает исходному посетителю или новому владельцу открыть заказ по собственному сеансу.

Схема базы не менялась. Для Source=Guest поле CustomerId хранит случайный идентификатор защищённой гостевой сессии; аккаунт Customer автоматически не создаётся. Оплата очищает именно гостевую корзину, сохраняя добавленные после оформления позиции.

Обновлены инструкции на страницах приложения, доставки, правовой информации и контекст помощника. Экспорт Vercel ждёт HTML версии 16 на Render; импорты JavaScript и кэш статических ресурсов обновлены согласованно.

## Проверка

- 107 из 107 .NET-тестов, включая 9 новых проверок гостевого оформления.
- 17 из 17 существующих JavaScript-проверок.
- Проверены изоляция чужой сессии, тот же телефон, подмена и применение токена к другому заказу, доступ к QR, повторное создание, ошибочная оплата, оплата при получении, CSRF, явное сохранение и отзыв гостевого доступа.
- Тестовый HTTP-клиент исправлен: cookie выбираются для фактического пути запроса, как в браузере; это позволяет проверять ограниченные по пути cookie.
- В браузере пройден заказ без регистрации через СБП, подтверждение демооплаты, статус, копирование ссылки, вход и появление заказа в истории. Проверено сохранение полей при добровольном входе до оформления.
- Проверена ширина 390 px: форма доступна без модального входа и горизонтальной прокрутки.

Оплата и телефонный вход сохраняют существующий демонстрационный режим. Реальные списания и SMS этим изменением не подключаются.
