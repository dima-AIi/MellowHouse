# Дополнение: функции админки Mellow House

19 октября 2026. Пользователь прислал ещё три скриншота как примеры функций и попросил обновить промпт. Это задание пока на планирование; код сайта не меняется до следующей команды.

Персональные данные, контакты, заказы, названия чужих товаров, цены и показатели из новых скриншотов не переносились. Сами новые скриншоты в проект не скопированы, поскольку содержат чужие контакты. Ниже сохранены только функциональные идеи. Исходные изображения не являются ассетами сайта.

## Что показывают примеры

- Отчёты: период, суммы продаж, себестоимость, маржа, маржинальность, сравнение товаров и топ продаж.
- Товары: добавление, список, фильтр категории, редактирование, удаление, цена и дополнительные сведения о товаре.
- Заказы: номер, статус, получение, оплата, состав с количеством и ценами, изменение статуса, история, действие возврата.
- По уточнению пользователя также нужны зарегистрированные клиенты, управление доступом и сброс пароля.

## Как адаптировать под кафе

1. **Обзор и отчёты** — общая сводка, аналитика по периоду, популярные товары и расчёт маржи при заполненной себестоимости.
2. **Каталог** — товары и категории в одном разделе. Категорию можно создать прямо при создании товара; отдельная копия раздела «Категории» в главной навигации не нужна.
3. **Заказы** — очередь, история, полный состав и настройки, статусы, локальный возврат. Ручной заказ сотрудника находится здесь же, без отдельного магазина или кассового модуля.
4. **Клиенты** — профили, история заказов, активность, блокировка, восстановление доступа и журнал действий.
5. **Настройки** — данные кафе, получение, оплата, рекламный контент и FAQ во внутренних вкладках.

Стиль: собственная композиция Mellow House, белый и лесной зелёный, существующие шрифты и компоненты. Чёрно-золотая тема и расположение чужого интерфейса не копируются.

Универсальная карточка товара содержит название, категорию, описание, состав, аллергены, фото, цену, порцию/единицу, доступность, сортировку и признаки рекомендаций. Применимые настройки задаются конструктором групп/опций. Себестоимость и пищевая ценность необязательны; не заполнять их выдуманными нулями. Штрихкоды и складской учёт из магазинного примера для текущего кафе не требуются.

Сброс пароля — одноразовый ограниченный по времени токен, собственный пароль выбирает клиент. Текущие пароли администратору не показываются. Для входа только по телефонному коду пароль не выдумывается. В локальной версии допустимо показать ссылку администратору один раз, без фактической отправки писем.

Оплата и готовность заказа — разные статусы. Возврат сейчас локальный, без реального движения денег. Числа аналитики вычисляются из данных приложения; неизвестная себестоимость показывается как неизвестная, а не как прибыль 100%.
