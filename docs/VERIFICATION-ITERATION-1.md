Это наблюдение не объявлено исправленным инициализацией IDE: полноценная проверка F5 в окне ещё нужна. Стандартное восстановление описано в [документации NuGet](https://learn.microsoft.com/en-us/nuget/consume-packages/package-restore); сообщение по виду похоже на отсутствие сведений в проектной системе IDE, но точная причина в этой среде не доказана.

## Серверная проверка

Использована настоящая SQLite, отдельные файлы тестов в `artifacts/test-data`, реальные HTTP endpoints через ASP.NET TestServer. EF InMemory не применялся.

- Цены размеров и добавок, аллергены, нормализация порядка и повторов опций; неизвестные и неприменимые значения отклоняются. Переданная клиентом цена не управляет оплатой.
- Добавление, редактирование, объединение одинаковых конфигураций, сохранение соседних строк, проверка количества и недоступных товаров.
- Гостевая корзина, объединение при входе, собственное избранное, запрет чужих заказов, CSRF, неверный код.
- Доставка/самовывоз, авторизация перед заказом, ошибка/отмена/повтор платежа, атомарный успех и очистка купленных позиций.
- Повтор запросов и конкурентные запросы создают один заказ/успех; снимки старого заказа сохраняются, повтор использует текущий каталог.
- Перезапуск TestServer с тем же файлом и cookies сохраняет корзину, вход и заказ. Публичная Production-демоавторизация не открывает другой профиль по тому же контакту из нового браузера.

## Покупательские сценарии в Chrome

Проверки выполнялись в отдельном headless Chrome через уже установленный Playwright 1.62.1, с новыми профилями и разрешёнными запросами только к localhost. Окна, cookies и аккаунты пользовательского Chrome не использовались.

Проверены главная и движение эффектов, статичная сетка фотокатегорий, горизонтальная лента на телефоне, все 10 разделов длинного меню, активный пункт, якорь, offset и возврат из товара. Во времени измерялись изменение opacity приветствия, появление отдельных рекламных строк после прокрутки и transform фотографии. Reduced motion оставляет текст доступным без прокрутки.

Раф настроен на овсяное молоко: **320 + 60 = 380 ₽**. BBQ с сыром: **390 + 60 = 450 ₽**, с исключением лука и соусом отдельно. Вместе **830 ₽**, доставка **190 ₽**, итог **1020 ₽**. Проверены сохранение и отмена правки, объединение, количество, удаление с отменой, обновление страницы, избранное и рекомендуемое.

Гость собирает корзину, закрывает вход без потери состава, вводит ошибочный и правильный код, продолжает оформление. Проверены обязательные поля, недоступная зона, самовывоз и доставка, прошлое и допустимое время, сохранение черновика, личного имени и адреса. Пройдены карта и СБП: успех, ошибка, отмена, смена метода и повтор. Отдельно смоделирована потеря ответа **после фиксации оплаты сервером**: повтор не создаёт второй заказ. Успех очищает корзину, история содержит снимок; повтор восстанавливает конфигурации по актуальной цене.

Полный мобильный путь пройден на 390 px. На 390/768/1024/1440 px основные страницы не имеют горизонтального переполнения. Проверены клавиатурный фокус диалогов, Escape и возврат фокуса, доступная отмена удаления, подписи форм, информационные страницы, ссылки футера, инструкции PWA и честное офлайн-состояние. При искусственно задержанном каталоге добавление ждёт настройки, а оформление неактивно до загрузки данных.

## Воспроизведение

Из корня `D:\дима\MellowHouse`:

```powershell
dotnet restore MellowHouse.sln
dotnet build MellowHouse.sln --no-restore
dotnet test tests/MellowHouse.Tests/MellowHouse.Tests.csproj --no-build --no-restore --logger "trx;LogFileName=MellowHouse.trx" --results-directory artifacts/TestResults
dotnet build MellowHouse.sln --configuration Release --no-restore
dotnet publish src/MellowHouse.Web/MellowHouse.Web.csproj --configuration Release --no-build --no-restore --output artifacts/publish
dotnet run --project src/MellowHouse.Web --launch-profile MellowHouse --no-build --no-restore
```

Браузерные скрипты: `tools/ui-check.cjs`, `tools/ui-edge.cjs`, `tools/ui-loading.cjs`. Нужны Node, Playwright и Chrome **только для повторения автоматической проверки**, сайт от них не зависит. Пакет можно указать через `MH_PLAYWRIGHT_PATH`, путь модулей — через `NODE_PATH`. Запускать последовательно при работающем localhost:5186. Сборку и publish выполнять после остановки web-процесса, чтобы Windows не блокировала apphost.

В среде Codex компилятор, VSTest testhost и Chrome потребовали разрешённого запуска вне ограниченной песочницы; штатный локальный запуск пользователя от этого режима Codex не зависит.

## Что действительно не проверялось

- Нажатие **F5/Ctrl+F5 непосредственно в окне Visual Studio**. Проверены сборка через установленную IDE и запуск того же launch profile через dotnet. Встроенный браузер не подключился к localhost; native computer-use остановился из-за неопределённого URL Chrome, дальнейшего управления пользовательским окном не было.
- Реальный Docker/OCI-запуск, подключение PostgreSQL, аккаунт Vercel, публичный URL и его cookies/proxy. Файлы и отдельные миграции подготовлены; инструкция — [DEPLOY-VERCEL-RU.md](../DEPLOY-VERCEL-RU.md).
- Реальные SMS, банковские платежи, приготовление и доставка: сайт явно демонстрационный.
- Большой наполненный каталог. После финального наполнения повторно проверить прокрутку, ассортимент, фотографии, применимость настроек и рекомендации.

Проверочный сервер остановлен перед передачей, чтобы профиль Visual Studio мог занять порт 5186. Рабочая база и все материалы сохранены.
