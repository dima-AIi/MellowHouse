# Запуск на Render

Dockerfile.vercel запускает deploy/start-web.sh от непривилегированного пользователя. По умолчанию скрипт только запускает приложение. Для одного демонстрационного экземпляра на Render задайте Database__InitializeOnStart=true: перед сервером выполняется штатный --migrate --seed. Ошибка подготовки прекращает запуск; успешный процесс сервера получает сигналы напрямую через exec.

Все заполнения защищены маркерами и сохраняют изменения администратора. Samples__Disabled=true создаёт 78 товаров без учебных продаж и клиентов. Production-администратор создаётся по Admin__Email/Admin__Password только при отсутствии администратора; повторный старт его пароль не меняет. Для нескольких экземпляров или полноценной production-инфраструктуры миграции выполняются отдельным управляемым шагом, а флаг отключается.

Neon URI преобразуется в формат Npgsql Host=…;Database=…;Username=…;Password=…;SSL Mode=VerifyFull;Channel Binding=Require. Секреты задаются через Render Environment, не в Git. Локальный файл импорта App_Data/render.env исключён из Git, Docker-контекста и publish. Содержимое не размещать в переписке или скриншотах.

Папка uploads доступна приложению на запись. На Free Render загруженные после deployment файлы не сохраняются при пересоздании экземпляра; перед реальной работой требуется постоянное объектное хранилище. Изображения из исходников входят в сборку и от перезапуска не теряются. Пользователи, заказы и ключи Data Protection хранятся в PostgreSQL.
